Добавлен раздел «Если содержимое скилла разошлось с реальностью» — правки в скилл по ходу работы заводятся через `spawn_task` (по образцу механизма в `tilda-helper`), а не молча. |
| 4.2 | август 2026 | В раздел 4 (Семантическое ядро 2.0) добавлена проверка семантики по фактическим данным: отчёт «Поисковые фразы» в Яндекс.Метрике (трафик и конверсии по факту) в связке с отчётом «Поисковые запросы» в Яндекс.Вебмастере (показы/клики/CTR/позиция, включая показы без клика) — вместе закрывают воронку показ → клик → визит → конверсия и позволяют сверить ядро с реальным спросом, а не только с прогнозом Вордстата. Указана честная оговорка про неполноту данных Метрики из-за политики передачи referrer. Добавлен соответствующий пункт в чек-лист готовности страницы. |
| 4.3 | август 2026 | Добавлен `scripts/wordstat_check.py` — прямая проверка частотности через Yandex Cloud Search API v2 (без стороннего SEO-комбайна, логика сверена с открытой реализацией KeyWai). Настройка ключа и использование — `references/wordstat-check.md`, ссылка добавлена в раздел 4. |
| 4.4 | август 2026 | Добавлен раздел 14 «Агентная готовность (Agentic Browsing)» — отдельный от GEO/AEO трек: готовность сайта к тому, что ИИ-агент (не человек) сам доводит транзакцию до конца (заявка/бронь/покупка), а не только цитирует контент. Источник — разбор статьи texterra.ru про подготовку данных/сайта/процессов к клиентским AI-агентам. В `references/geo-ai-poisk.md` — полная методология и чек-лист (источник критичных данных, единство данных сайт↔карточки, устойчивый интерфейс для DOM-агента, транзакционная Schema, проверка через Lighthouse → Agentic Browsing, приоритизация под клиента). Явно разграничена зона SEO-диагностики и зона `tilda-helper`/разработки (интеграции с CRM, права доступа агента — вне скилла). |
